# Abinit Run Tests

This skill automates the execution of the ABINIT test suite using the `runtests.py` python script.
This skill allows you to run specific suites (e.g., `built-in`, `fast`, `v1`), parallel tests,
or tests in a specific directory.

The `runtests.py` script is located in `${ABINIT_TOPDIR}/tests/runtests.py`
where `${ABINIT_TOPDIR}` is the top-level directory of the git repository that can be obtained with:

```bash
ABINIT_TOPDIR=`git rev-parse --show-toplevel`
```

The exit code of the scripts is the number of failing tests.

Use the `--help` option to access the documentation and the CLI examples.

Read `tests/README.md` for suite registration and `TEST_INFO` guidance.
Run from the repository root and pass the build tree explicitly when discovery is ambiguous:

```bash
./tests/runtests.py 'v1[1]' --build-tree _build
./tests/runtests.py 'v1[1:3]' --build-tree _build --dry-run
./tests/runtests.py paral --build-tree _build --num-mpi-processors 4
```

The build tree must contain `config.h` and the required executables.
The test database is regenerated by default; use `--use-cache` only when it is known to match the
active branch.

### Common Pitfalls

- **Recompilation**: If Fortran changed, rebuild first or use `--make 6` to invoke Make with six jobs.
- **MPI support**: For `--num-mpi-processors 4`, ensure the build supports MPI and its launcher is available.
- **References**: Do not update reference files merely to silence a failure; explain and validate the
  numerical or behavioral change first.
