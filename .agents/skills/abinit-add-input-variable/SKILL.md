# Add Abinit Input Variable

Adding an input variable is a cross-cutting implementation task, not a mechanical text insertion.
First read the relevant sections of `doc/developers/developers_howto.md` and
`doc/developers/abimkdocs.md`, then inspect a recent variable with the same type and shape.

The helper only creates scaffolding for simple scalar cases.
Do not use it unattended: its TODOs are not an implementation, and every insertion requires manual
placement and review.

## Usage

You can invoke this skill by running the provided Python script from the root of the abinit project:

```bash
python .agents/skills/abinit-add-input-variable/scripts/add_input_variable.py --name myvar --type integer --default "0" --description "A new test variable"
```

### Arguments

- `--name`: The name of the new variable (must not end with a digit).
- `--type`: The Fortran type of the variable (e.g., `integer`, `float`, `logical`, `character`).
- `--default`: The default value to insert in `indefo1` (`m_invars1.F90`).
- `--description`: A short description of the variable (currently only used for the log
  message; documentation in `abimkdocs/variables_abinit.py` is not yet generated by this
  skill and must still be added by hand).

### What it does

1. Adds the variable to `dataset_type` in `src/44_abitypes_defs/m_dtset.F90`.
2. Adds a `! TODO` stub to `chkvars` (same file).
3. Adds the default value assignment to `indefo1` in `src/57_iovars/m_invars1.F90`.
4. Adds a `! TODO` read-logic stub to `invars1` (same file, via `call intagm(...)`).
5. Adds a `! TODO` print stub to `src/57_iovars/m_outvar_a_h.F90`, `m_outvar_i_n.F90`, or
   `m_outvar_o_z.F90`, chosen by the first letter of the variable name.
6. Adds a `! TODO` consistency-check stub to `chkinp` in `src/57_iovars/m_chkinp.F90`.

There is no `dtset_copy`-style step: multi-dataset default inheritance in this codebase is
handled by `m_invars1.F90`'s own dataset-0 propagation logic, not a per-field copy routine,
so a new variable doesn't need one either.

WARNING:

This skill relies on regular expressions to patch Fortran code and may leave partial changes if a
later insertion fails.
Use `git diff` to verify every change.

Before finishing, also:

1. Determine the owning executable, shape, units, allowed values, version, and multi-dataset behavior.
2. Replace every generated TODO with correct parsing, printing, and consistency logic.
3. Add complete documentation to the appropriate `abimkdocs/variables_*.py` database.
4. Add and register a regression test as described in `tests/README.md`.
5. Run `pytest abimkdocs_tests/test_variables.py -q`, compile the affected executable, and run the
   targeted regression test.

ABINIT and MULTIBINIT share parts of `chkvars`.
Do not infer variable ownership solely from that routine's source location.
